# NPLATFORM 기능 정의 · 업무 프로세스

> 2026-08-18 기준 · 역할 4종 체계 확정판.
> 원칙: "공개하지 않는 것이 기능이다 — 매입조건에 매칭되는 딜만 선별하여 공개합니다."

---

## 1. 역할 정의 (4종)

| 역할 | 코드 | 정의 | 권한 요약 |
|---|---|---|---|
| **운영관리자** | ADMIN / SUPER_ADMIN | 엔플랫폼 운영진 | 모든 화면 등록·수정·삭제 (CRUD) |
| **운영 파트너** | PARTNER | 운영 협력사 (자문사 등) | 운영관리자와 동일 화면 **열람만** — 버튼·입력 비활성화 |
| **매각 회원** | SELLER | 은행 · 저축은행 · AMC · 대부업체 · 캐피탈 · 보험사 | 매각의뢰 접수 + 본인 매물 현황 관리 |
| **매입 회원** | BUYER | 법인 · 대부업체 · AMC · 투자운용사 · 개인 자산가 · 개인 투자자 | 매입조건 등록 + 자동매칭 열람 + NDA |

- 회원가입 유형은 **매각 회원 / 매입 회원 2종만** 노출 (무료 · 관리자 승인제).
- 운영 파트너는 운영진이 직접 계정 부여. 일반회원(VIEWER)은 legacy 호환용으로만 유지.

| 언론보도 | 제목·URL·썸네일 CRUD → NPLATFORM 소개 페이지 반영 (새창 열기) |
| 메인 지표 입력 | KPI 5종 + 티커 4종 입력 → 메인·자동매칭 KPI·라이브 티커 자동 반영 |

## 3. 주요 업무 프로세스 (9)

### P1. 회원 가입 · 승인
1. 가입: 유형(매각/매입) 선택 → 정보 입력 → 명함·사업자등록증 첨부 → 접수 (상태 `승인대기`)
2. 운영관리자: 회원 승인에서 [첨부] 확인 → **승인(활성)** 또는 **거절**
3. 승인된 회원만 매각의뢰/매입조건/NDA 이용 가능
- 저장소: `users` (+auth 메타)

### P2. 매각의뢰 접수 · 등록 (컨시어지)
1. 매각 회원: 파일 첨부 + 마케팅 조건 협의 → 접수 (접수함 티켓 생성, "운영진이 개별 연락")
2. 운영관리자: 검토·비식별화 → 매물 등록 대행 (관리번호 N-XX 자동 채번) → 상태 `검토대기`
3. **승인** 시 자동매칭 리스트 등재 / **거절** 시 비노출
4. 세부내역(표준탬플릿 40필드) 입력 — 운영자·매각 회원 공동 편집
- 저장소: `support_tickets` → `npl_listings` + `listing_marketing.detail`

### P3. 마케팅 진행 관리
1. 운영관리자: 매각의뢰 현황 [마케팅] → 8개 채널 체크(즉시 저장) + 상담 수 입력
2. 매각 회원: 내 매물에서 실시간 확인 (관심·NDA는 자동 집계)
- 저장소: `listing_marketing.checklist / consult_count / interest_count / nda_count`

### P4. 매입조건 등록 · 자동매칭
1. 매입 회원: 조건 등록 (우선순위별 다건)
2. 매칭 엔진: 지역 ∧ 유형 ∧ 금액대 대조 → **조건에 맞는 딜만 리스트 공개**
3. 조건 없으면: 블러 샘플 + "매입조건 등록 시 매칭 진행"
- 저장소: `npl_demands` · 매칭: `/api/v1/matching/summary`

### P5. NDA 요청 · 승인 · 상세 공개
1. 매입 회원: 리스트에서 [NDA 요청] → 관리번호 기준 전자서명 제출 (상태 `운영사 검토`)
2. 운영관리자: NDA·계약에서 요청별 **승인/거절**
3. **승인** → 매입 회원이 리스트 클릭 시 세부내역 열람 (채권기관·담당자 4필드 제외)
4. 3자 공유: 관리자(처리) · 매입 회원(내 NDA 상태) · 매각 회원(내 매물 NDA 현황)
- 계약: NDA 당사자 = 엔플랫폼(트랜스파머 주식회사) · 유효기간 1년
- 저장소: `npl_ndas`(서명 원본) + `listing_marketing.nda_requests`(상태)

### P6. 딜 진행 관리
1. 운영관리자: 딜 단계 클릭 등록 — 관심등록 → 실사진행 → 가격협의 → 최종계약
2. **첫 단계 등록 시 매칭날짜 자동 기록** (수동 수정 가능)
3. 매입 회원 알림은 매칭날짜 **이후** 업데이트만 발송 (기준 데이터 완비 · 발송 채널 연동은 후속)
4. NPL 상태(진행중/협의중/매각완료)는 운영자·매각 회원 양쪽에서 수정 → 리스트 앞단 배지 표시
- 저장소: `listing_marketing.deal_stage / matched_at / npl_status`

### P7. 진행종료 · 매각완료
1. 매각 회원: [진행종료 요청] → 접수함 티켓 (상태 "종료 요청됨 · 운영사 승인 대기")
2. 운영관리자: 확인 후 매각의뢰 현황에서 **거절(비노출)** 또는 상태 **매각완료** 처리
- 저장소: `support_tickets` + `npl_listings.status` / `listing_marketing.npl_status`

### P8. 메인 콘텐츠 운영
- 메인 지표 입력(KPI 5 + 티커 4) / 히어로 카드 / 하이라이트 8건(이미지 중심) / 언론보도(썸네일+새창) — 저장 즉시 공개 화면 자동 반영
- 저장소: `api_configs` · `main_hero` · `main_highlights` · `press_articles`

### P9. 문의 · 접수 대응
1. 유입: 1:1 문의 위젯(02-555-2822 병기) · 매각의뢰 · 진행종료 요청
2. 운영관리자: 접수함에서 탭별 확인 → 상태 전환(접수→처리중→완료) → 유선/이메일 개별 대응
- 저장소: `support_tickets`

## 5. 회원가입 프로세스 — 역할별 분기 (설계 확정 · 2026-08-18)

### 5-1. 분기 원칙
- 가입 첫 화면에서 **매각 회원 / 매입 회원** 선택 → 이후 입력 스텝이 완전히 달라진다.
- 매입 회원은 두 번째 스텝에서 **법인 / 개인자산가** 세부유형을 선택한다 (코드: BUYER_INST / BUYER_INDV — 표기는 "매입 회원"으로 통합, 관리자 화면에서만 세부 구분 노출).
- **매입 회원은 가입 플로우의 마지막 스텝이 곧 매입조건 등록**이다 — 가입 완료 = 조건 1건 이상 확보. 관리자 승인 즉시 매칭이 시작된다.

### 5-2. 매각 회원 가입 (기관 중심)
| 스텝 | 입력 |
|---|---|
| 1 | 유형 선택: 매각 회원 |
| 2 | 기관유형(은행·저축은행·상호금융·AMC·대부·캐피탈·보험 등 12종) · 기관명 · 사업자등록번호 |
| 3 | 담당자명 · 직책 · 연락처 · 이메일 · 비밀번호 |
| 4 | 첨부: **사업자등록증(필수)** · 명함 |
| 5 | 약관 동의 → 접수 (승인대기) |

### 5-3. 매입 회원 가입 (법인 / 개인자산가 분기)
| 스텝 | 법인 | 개인자산가 |
|---|---|---|
| 1 | 유형 선택: 매입 회원 | 동일 |
| 2 | 세부유형: **법인** | 세부유형: **개인자산가** |
| 3 | 법인명 · 사업자등록번호 · 담당자명 · 직책 | 성명 · (선택) 투자 가능 규모 |
| 4 | 연락처 · 이메일 · 비밀번호 | 동일 |
| 5 | 첨부: **사업자등록증(필수)** · 명함 | 첨부: 명함 (선택) |
| 6 | **매입조건 등록** — 지역 · 담보유형 · 금액대 (우선순위별 다건, 가입 후 수정 가능) | 동일 |
| 7 | 약관 동의 → 접수 (승인대기) | 동일 |

- 승인 전에도 조건은 저장되며, **승인되는 순간부터 매칭 풀에 편입**된다.

## 6. 매물 라이프사이클 · 상시 매칭 파이프라인 (핵심 설계)

### 6-1. 대원칙
> **매물은 "진행 종료" 전까지 계속 살아 있다.**
> 알림이 갔다고 거래가 체결되는 것이 아니다. 매물이 살아 있는 동안 신규 매입 회원 가입과 신규 매입조건 등록이 계속 유입되고, 그때마다 **재매칭 → 알림**이 반복된다. 하나의 매물에 여러 매입 회원이 서로 다른 협상 단계에 동시에 존재할 수 있다.

### 6-2. 매물 상태 (라이프사이클)
```
접수(매각의뢰) → 검토대기 → 승인·공개(진행중) ⇄ 협의중 → 매각완료
                     ↘ 거절                    ↘ 진행종료(철회 — 매각 회원 요청 + 운영 승인)
```
- **진행중 · 협의중** 상태의 매물만 매칭 풀에 존재한다 (협의중이어도 리스트에 유지 — 배지로 표시).
- **매각완료 · 거절 · 종료** 시 매칭 풀과 리스트에서 제외.

### 6-3. 이벤트 → 재매칭 → 알림 매트릭스
| 이벤트 | 매칭 동작 | 알림 대상 |
|---|---|---|
| E1 신규 매물 승인·공개 | 기존 **모든 살아있는 매입조건**과 대조 | 매칭된 매입 회원 전원 — "조건에 맞는 신규 NPL 등록" |
| E2 신규 매입조건 등록 (신규 가입 포함, 승인 후) | **모든 살아있는 매물**과 대조 | 해당 매입 회원 — "조건에 맞는 매물 N건" (리스트 즉시 노출) |
| E3 매물 정보 변경 (협의가 인하, 세부내역 갱신) | 기존 매칭 유지 | 매칭·관심·NDA 회원 — 단 **매칭날짜 이후 변경분만** |
| E4 매물 상태 변화 (진행중→협의중, →매각완료) | 협의중은 풀 유지, 완료 시 제외 | 관심·NDA 등록 회원 — 상태 변경 알림 |
| E5 NDA 승인/거절 | — | 해당 매입 회원 (+매각 회원 대시보드 반영) |
| E6 진행종료 승인 | 풀 제외 | 관심·NDA 회원 — "진행 종료" 통지 |

### 6-4. 매입 회원별 딜 퍼널 (매물 1건 × 회원 N명 병행)
```
[매칭됨] → [관심등록 ♥] → [NDA 요청] → [운영사 승인] → [상세 검토]
   → [상담 · 1차 미팅 (엔플랫폼)] → [가격 협의 · 2차 미팅 (매각기관 동행)]
   → [최종계약] → 운영자 매각완료 처리 → 나머지 회원에게 종료 통지
```
- 퍼널은 **회원별로 독립** 진행 (NDA·관심·상담은 회원 단위 기록).
- 매물 단위 딜 단계(관심등록→실사진행→가격협의→최종계약)는 **가장 앞선 협상 기준**으로 운영자가 관리.
- 최종계약 합의가 나와도 운영자가 **매각완료 처리하기 전까지 매물은 협의중으로 유지** — 병행 협상 이탈 대비.

### 6-5. 구현 현황 매핑
| 설계 요소 | 상태 |
|---|---|
| 매물 상태 3종(진행중/협의중/매각완료) + 검토대기/거절/종료 요청 | ✅ 구현 |
| 조건 기반 리스트 게이팅 · 실매칭 엔진(지역∧유형∧금액대) | ✅ 구현 |
| NDA 회원별 요청·승인 · 딜 단계 · 매칭날짜 자동 기록 | ✅ 구현 |
| 가입 분기 폼 (매각/매입 · 법인/개인자산가 · 가입 중 조건 등록) | 🔲 구현 예정 |
| 이벤트 알림 발송 (E1~E6 · 이메일/문자/인앱) | 🔲 기준 데이터 완비 · 발송 연동 예정 |

## 7. 알림 정책 (2026-08-18 확정)

### 7-1. 발송 등급 — 역할별 주기 차등 (2026-08-18 수정)
| 구분 | 매입 회원 | 매각 회원 |
|---|---|---|
| **즉시 (건별)** | NDA 승인/거절 · 검토 중 매물의 진행종료 · (승격) 관심/NDA 매물의 가격 인하 | 가입 승인 · 매물 승인(공개 시작) · NDA 요청 접수 · 딜 단계 변경 |
| **정기** | **일일 다이제스트** (평일 오전 9~10시) — 신규 매칭 매물 중심, 변동 있으면 포함 | **주간 리포트** (매주 월요일 오전) — 지난주 내 매물 활동 요약 |

- 공통: **보낼 내용이 있을 때만 발송** (빈 알림 금지 · 주말 미발송).
- 변동은 실제로 드물 것으로 보고 매입 다이제스트는 **신규 중심**으로 구성. 거래량 증가 시 '신규 매칭'을 즉시 등급으로 승격.

### 7-2. 매입 회원 다이제스트 — 하이라이트 **최대 2건**
```
[엔플랫폼] 오늘의 매칭 브리핑 — 신규 3건
🆕 N-12 서울 강남구 · 오피스 — 감정가 450억 · 협의가 198억
🆕 N-13 부산 해운대구 · 호텔 — 감정가 215억 · 협의가 118억  (외 1건)
👉 전체 보기 (링크)
```
- 하이라이트는 **최대 2건** — 기본은 신규 2건. 변동이 있는 날만 신규 1 + 변동 1로 구성 (변동은 이전값→현재값 표기)
- 선정 순서: ① 우선순위 1 조건 매칭 ② 감정가 큰 순. 변동 대표는 관심·NDA 등록 건 우선
- 하이라이트 내용은 공개 리스트 수준까지만 (알림 채널은 마스킹 정책 적용, 상세는 로그인 후)

### 7-2b. 매각 회원 주간 리포트 — 지난주 내 매물 활동
```
[엔플랫폼] 주간 마케팅 리포트 (8/11~8/17) — N-07 외 2건
· 매입 회원 알림 발송 12건 (신규 매칭 안내)
· 신규 매칭 매입 회원 +5 · 관심 +3 · NDA 요청 +2 · 상담 +1
· 마케팅 진행: 땅집고옥션 이메일 발송 · 엔플랫폼 메인 노출
👉 내 매물 대시보드 보기 (링크)
```
- **주간 알림 발송 건수**(내 매물이 매입 회원에게 안내된 횟수)를 반드시 포함 — "마케팅이 되고 있다"는 핵심 증거
- 매물별 소계 + 합계. 활동이 0이면 미발송

### 7-3. 리스트 링크 — 알림 기준 구간 고정
```
이번 알림의 대상 구간 = [직전 알림 발송 시각, 이번 알림 발송 시각]
링크: /exchange?alert=2026-08-19T0900&until=2026-08-20T0900
```
- 신규 = 구간 내 승인·공개(published_at) / 변동 = 그 이전 공개 + 구간 내 수정(updated_at)
- 링크 진입 시: '신규·변동만' 필터 자동 활성 + 기준 배너("8/19 09:00~8/20 09:00 기준 · 신규 2 · 변동 1") + 행 배지(NEW · 가격↓ · 정보갱신)
- 기준이 URL에 고정 → **며칠 뒤 열어도 알림과 동일한 목록** (알림에 적힌 것 = 화면에 보이는 것)
- 기준 분리: 알림 링크 = 알림 구간(고정) / 직접 방문 '신규·변동만' 토글 = 마지막 접속(last_seen) 이후

## 9. 개발 백로그 (2026-08-18 · 기획서 기반 확정)

### D0. 공통 UI 규칙 — 전 리스트 적용 (P1)
- **모든 리스트에 검색 + 서버 페이지네이션** (기본 20건/페이지): 자동매칭 · 관심매물 · 내 매입조건 · 내 매물 · 회원 승인 · 매각의뢰 현황 · 매입조건 현황 · NDA·계약 · 수익률 분석 · 접수함 · 하이라이트 · 언론보도
- **상세는 별도 페이지 이동 금지** — 공통 DetailPane 컴포넌트:
  - 화면 폭 ≥ 1280px: **2단 프레임** (좌 리스트 + 우 상세 패널, 행 클릭 시 우측 갱신)
  - 좁은 화면: **모달**로 동일 내용
  - 기존 /listing-detail 페이지는 인쇄·딥링크·엑셀용으로만 유지
- 리스트 행 선택 상태 표시 + 키보드 ↑↓ 이동

### D1. 회원 모델 — 복수 역할 (P1 · 스키마 변경)
> **회원은 매각 회원이면서 동시에 매입 회원일 수 있다.**
- `users.roles` 를 배열로 (예: ["SELLER","BUYER"]) + `buyer_kind`(CORP/INDIVIDUAL) — 기존 단일 role 은 대표 역할로 유지(호환)
