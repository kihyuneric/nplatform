# 엔플랫폼(NPLATFORM) 운영설계서

> **v2.0 (2026-08-18 전면 재작성)** — 실제 서비스 화면 기준.
> 원칙: **이 문서의 모든 기능은 실제 화면 URL과 1:1로 대응한다.**
> 화면에 없는 기능(정산·투자등급·티어·크레딧·분석 리포트 등)은 이 문서에 없으며, 서비스에도 없다.
> 하나의 기능은 하나의 폼/화면만 가진다 — 같은 기능이 화면마다 다른 형태로 존재하지 않는다.

---

## 1. 서비스 철학과 화면 지도

**"공개하지 않는 것이 기능이다 — 매입조건에 매칭되는 딜만 선별하여 공개합니다."**

### 1-1. 전체 화면 지도 (이 문서가 다루는 화면의 전부)

|---|---|---|---|

### 1-2. 서비스에 없는 것 (문서·화면 어디에도 두지 않는다)

정산/결제/크레딧 · 투자자 등급(L1~) · 구독 티어 · 조회수 분석 리포트 · 공지사항 메뉴 · 커뮤니티 · 전문가 서비스 · 딜룸 · KYC 등급 심사(가입 승인으로 대체)

## 2. 역할 4종 (이 외 역할은 없다)

| 역할 | 코드 | 가입 경로 | 권한 요약 |
|---|---|---|---|
| 운영관리자 | ADMIN | 내부 지정 | 관리자 전 화면 CRUD |
| 운영 파트너 | PARTNER | 내부 지정 | 관리자 전 화면 **열람 전용** (수정·삭제 불가) |
| 매각 회원 | SELLER | 회원가입 | 매각의뢰 · 내 매물 관리 |
| 매입 회원 | BUYER | 회원가입 (법인 CORP / 개인자산가 INDIVIDUAL) | 매입조건 · 자동매칭 · NDA · 열람 |

- 회원가입 화면에는 **매각 회원 / 매입 회원 2종만** 노출된다.
- 한 회원이 **매각+매입 겸용** 가능 (roles 배열). 겸용 시 마이페이지 메뉴는 합집합.
- 겸용 부여는 관리자 회원 상세의 "역할 관리"에서 저장한다.

## 3. 역할별 기능정의 — 서비스 ↔ 마이페이지 ↔ 관리자 연동표

> 각 행이 하나의 기능이다. 세 열이 같은 데이터를 바라본다(연동). "—"는 해당 구역에 화면이 없다는 뜻이다.

### 3-1. 매입 회원 (BUYER)

| # | 기능 | 서비스 화면 | 마이페이지 | 관리자 연동 |
|---|---|---|---|---|
| B1 | 회원가입 (법인/개인자산가 분기, 사업자번호·명함·사업자등록증 첨부) | `/signup` | — | `/admin/users` 승인 대기로 접수 |
| B2 | 매입조건 등록 — **가입 마지막 스텝도 이 폼으로 이동** | `/exchange/demands/new` | `/my/demands` (같은 API로 목록·수정·삭제, 신규 등록 버튼은 서비스 폼으로 연결) | `/admin/demands` 전체 조건 현황 |
| B3 | 자동매칭 리스트 열람 (매칭 조건 기준 선별 공개, 검색·필터·페이지네이션) | `/exchange` | `/my` 대시보드 "이번 주 브리핑" 요약 | `/admin/listings` 에서 승인한 매물만 노출 |
| B4 | 관심 등록 ♥ | `/exchange` 리스트에서 | `/my/portfolio` 관심매물 목록 | 내 매물(매각)·마케팅 현황의 "관심 N" 집계에 반영 |
| B5 | NDA 전자서명 요청 (관리번호 N-XX 기준) | `/exchange` 상세 패널에서 서명 제출 | `/my/agreements` + 대시보드 NDA 카드 (미제출→제출 완료→운영사 검토→승인/거절) | `/admin/agreements` 에서 검토·승인·거절 |
| B6 | 승인 후 세부내역 열람 (채권기관·담당자명·직책·연락처 4필드는 항상 제외) | `/exchange` 상세 패널 (열람 모드) | — | 관리자는 4필드 포함 전체 열람 |
| B7 | 알림 — 일일 다이제스트(신규 매칭 + 하이라이트 최대 2건 + `?alert=` 구간 링크) | 이메일 + `/exchange?alert=날짜` | `/my/inbox` 인앱 알림 · `/my/settings` 수신 설정 | 발송: Vercel Cron `/api/v1/cron/digest?type=daily` |

### 3-2. 매각 회원 (SELLER)

| # | 기능 | 서비스 화면 | 마이페이지 | 관리자 연동 |
|---|---|---|---|---|
| S1 | 회원가입 (기관 유형, 사업자번호 필수) | `/signup` | — | `/admin/users` 승인 대기로 접수 |
| S2 | NPL 매각의뢰 (컨시어지 접수 폼) | `/exchange/sell` | `/my/seller` "새 매물 등록" 버튼도 같은 폼 | `/admin/listings` 검토대기로 접수 → 승인/거절 |
| S3 | 내 매물 현황 (매물명·전체주소 마스킹 없음 / 채권액 / 상태 / 매칭 / 마케팅 / 등록일) | — | `/my/seller` (검색·페이지네이션) | `/admin/listings` 와 같은 저장소 실시간 공유 |
| S4 | 상태 변경 — **진행중 / 협의중 / 매각완료 3종만** | — | `/my/seller` 에서 직접 select | 관리자 마케팅 패널과 동일 값 |
| S5 | 매칭 매입사 확인 — 실매칭(매입조건 대조) 결과만, 매칭 등록일은 운영사 자동 기록 | — | `/my/seller` "N개사 · 실시간" | `/api/v1/matching/summary` 공용 |
| S6 | 마케팅 진행 확인 (8채널 체크리스트 + 관심·NDA·상담 집계 + 딜 진행 단계) | — | `/my/seller` 읽기 (상담·체크리스트는 운영사 입력) | `/admin/listings` [마케팅] 패널에서 입력 |
| S7 | NDA 진행상황 확인 (요청자·상태·일자) | — | `/my/seller` 매물별 표시 | `/admin/agreements` 승인 결과 실시간 반영 |
| S8 | 진행종료 요청 (운영사 승인 후 종료) | — | `/my/seller` 액션 → "종료 요청됨" | `/admin/inbox` 티켓 접수 → 처리 |
| S9 | 알림 — 주간 리포트 (NDA +7일 · 관심 · 상담 · 마케팅 진행) | 이메일 | `/my` · `/my/seller` "주간 활동 요약" 블록과 동일 기준 · `/my/inbox` | 발송: Vercel Cron `/api/v1/cron/digest?type=weekly` |

### 3-4. 운영 파트너 (PARTNER)

관리자와 **동일 화면을 열람 전용**으로 사용한다 (버튼·입력 비활성 + "열람 전용" 배너). 별도 기능 없음.

## 4. 업무 프로세스 (E2E)

### P1. 매입 회원 흐름 (가입 → 열람)
```
/signup (매입 선택 · 법인/개인 분기)
  → 가입 완료 즉시 /exchange/demands/new 로 이동   ← 서비스와 동일한 유일 폼
  → 관리자 /admin/users 승인 (보류 시 사유 메모)
  → /exchange 자동매칭 리스트 공개 (조건 매칭 건만)
  → 관심 ♥ 등록 → /my/portfolio
  → NDA 전자서명 제출 (N-XX 기준)
  → 관리자 /admin/agreements 승인
  → 세부내역 열람 (채권기관·담당자·직책·연락처 4필드 제외)
```

### P2. 매각 회원 흐름 (의뢰 → 종료)
```
/signup (매각 선택)
  → 관리자 승인
  → /exchange/sell 매각의뢰 접수
  → 관리자 /admin/listings 검토 → 승인 (거절 시 비노출)
  → 자동매칭 + 마케팅 8채널 진행 (운영사 입력)
  → /my/seller 에서 상태·매칭·마케팅·NDA 실시간 확인
  → 협의중 → 매각완료  또는  진행종료 요청 → 운영사 승인 → 종료
```

### P3. NDA 2단계 (관리번호 기준)
```
1단계  NDA 전자서명   : 미제출 → 제출 완료      (매입 회원)
2단계  운영사 검토·승인: 미승인 → 승인 완료      (관리자)
승인 후: 매입 회원 세부 열람 (항상 제외 4필드: 채권기관 · 담당자명 · 직책 · 연락처)
매각 회원 본인 매물은 마스킹 없음.
```

### P4. 상시 매칭 파이프라인
신규 매물 승인 · 신규 매입조건 등록 · 조건 수정이 있을 때마다 매칭은 계속 살아 움직인다.
매칭 결과는 `/my/seller` 매칭 매입사 수와 일일 다이제스트 발송 대상 계산에 공용으로 쓰인다.

## 5. 알림 정책 (구현 기준)

| 알림 | 대상 | 시점 | 채널 | 내용 · 링크 |
|---|---|---|---|---|
| 일일 다이제스트 | 매입 (활성) | 매일 KST 08:00 | 인앱 + 이메일 | 신규 매칭 N건, 하이라이트 **최대 2건**, `/exchange?alert=기준일` (구간 고정 링크 — 기준일 이후 등록 건만 + NEW 배지) |
| 주간 리포트 | 매각 (활성) | 매주 월 KST 08:00 | 인앱 + 이메일 | NDA +7일 · 관심 누적 · 상담 누적 — 대시보드 "주간 활동 요약"과 동일 기준, `/my/seller` |
| NDA 결과 | 요청한 매입 회원 | 승인/거절 즉시 | 인앱 + 이메일 | 승인 시 열람 안내 |
| NDA 신규 요청 | 매물 소유 매각 회원 | 제출 즉시 | 인앱 | `/my/seller` |
| 가입 승인/거절 | 해당 회원 | 처리 즉시 | 인앱 + 이메일 | |
| 수신 설정 | 전 회원 | — | `/my/settings` | 유형별 인앱/이메일 개별 ON·OFF (`notification_preferences`) — 다이제스트 발송이 이 설정을 존중 |

변동이 거의 없는 서비스 특성상 **알림은 요약(다이제스트) 중심**이고, 대시보드 블록이 알림의 화면 버전이다.

## 6. 정보 공개 3단계

| 단계 | 공개 범위 | 화면 |
|---|---|---|
| 1. 리스트 공개 | 관리번호(N-XX) · 지역(동 단위) · 담보유형 · 감정가 · 채권원금 · 채권최고액 · 협의가 · 면적 · 등록일 | `/exchange` |
| 2. NDA 승인 후 | 세부내역 표준 40필드 (전체주소 · 채권 상세 · 서류) | 상세 패널 |
| 3. 항상 비공개 | **채권기관 · 담당자명 · 직책 · 연락처** — 매입 회원에게는 어떤 단계에서도 비공개 | 관리자·해당 매각 회원만 |
