# 엔플랫폼 운영기획서 v3 — 제로베이스 CRUD 재설계

> **2026-08-18** — 기존 개발에 결합되지 않은 백지 설계.
> 접근: 서비스는 **5개 핵심 데이터** 위에서 돌아가고, 모든 화면(서비스·마이페이지·관리자)은
> 그 데이터에 대한 **CRUD(생성·조회·수정·삭제)의 조합**일 뿐이다.
> 이 문서에 없는 화면·기능·데이터는 만들지 않는다. 재개발 시 이 문서가 유일한 기준.

---

## 0. 설계 원칙

1. **데이터가 먼저, 화면은 나중** — 화면은 "누가 어떤 데이터를 CRUD 하는가"로만 정의한다.
2. **하나의 데이터에 하나의 폼** — 같은 데이터를 만지는 화면이 두 개면 하나는 잘못된 것이다.
3. **회원이 만든 것은 회원 화면에, 운영자가 만든 것은 관리자 화면에** — 그리고 서로의 결과가 상대 화면에 실시간으로 보인다(연동).
4. **필수만** — 정산·티어·크레딧·등급·분석리포트·커뮤니티·딜룸은 서비스에 없다. 어떤 화면에도 두지 않는다.

## 1. 핵심 데이터 5 + 운영 콘텐츠 1

| # | 데이터 | 정의 | 생명주기(상태) |
|---|---|---|---|
| E1 | **회원** Member | 계정 + 역할(매각/매입, 겸용 가능) + 승인 상태 | 승인대기 → 활성 / 보류(사유) / 거절 / 차단 / 탈퇴 |
| E2 | **매물** Listing | 매각의뢰로 생성되는 NPL 물건 (표준 40필드 + 관리번호 N-XX) | 검토대기 → 공개(진행중 → 협의중 → 매각완료) / 거절 / 종료 |
| E3 | **매입조건** Demand | 매입 회원의 매칭 기준 (지역·유형·금액대·우선순위) | 활성 / 삭제 |
| E4 | **NDA** NdaRequest | 매물 × 매입회원의 열람 계약 (2단계) | 제출 완료 → 운영사 검토 → 승인 / 거절 |
| E5 | **알림** Notification | 이벤트 기록 + 발송(인앱·이메일) | 미읽음 → 읽음 |
| E6 | 운영 콘텐츠 | 메인 히어로 · 하이라이트 8 · 언론보도 · 지표 9종 | 관리자 CRUD 전용 |

파생 데이터(별도 화면 없음): 마케팅 진행(E2에 종속: 8채널 체크·상담수·딜단계·매칭일), 관심(E2×회원 북마크), 문의 티켓(접수함으로만).

## 2. 페르소나 5 — 가입부터 종료까지 한 줄 여정

| 페르소나 | 여정 |
|---|---|
| P1 매각 회원 (금융기관·대부업) | 가입(기관정보·사업자번호·첨부) → **승인 대기** → 매각의뢰 제출 → 운영사 검토·공개 → 마케팅/매칭/NDA 현황 지켜봄 → 상태 변경(협의중·매각완료) 또는 진행종료 요청 |
| P2 매입 회원 · 법인 | 가입(법인·사업자번호·첨부) → **매입조건 등록(가입 마지막 스텝 = 서비스 폼)** → 승인 대기 → 자동매칭 리스트 열람 → 관심 → NDA 제출 → 승인 후 세부 열람 → 오프라인 협의 |
| P3 매입 회원 · 개인자산가 | P2와 동일 (사업자번호 대신 투자규모 선택 입력) |
| P4 겸용 (매각+매입) | P1 + P2 화면의 **합집합** — 별도 화면 없음 |
| P5 운영관리자 / 파트너 | 모든 데이터의 검토·승인자. 파트너는 동일 화면 **R(조회)만** |

## 3. CRUD 권한 매트릭스 (핵심 — 이 표가 전체 서비스다)

C=생성 R=조회 U=수정 D=삭제 · ( )=조건부

| 데이터 | 매각 회원 | 매입 회원 | 관리자 | 파트너 |
|---|---|---|---|---|
| E1 회원 (본인) | R·U (프로필·비밀번호) | R·U | — | — |
| E1 회원 (타인) | — | — | R·U (승인·보류·거절·차단·역할·비번초기화·탈퇴) | R |
| E2 매물 (본인) | C(매각의뢰)·R(마스킹 없음)·U(상태 3종만)·D요청(진행종료) | — | R·U(전체 필드·검토승인·마케팅)·D | R |
| E2 매물 (타인) | — | R(리스트: 공개 9필드 / NDA 승인 후: 40필드 − 항상제외 4필드) | R (전체) | R |
| E3 매입조건 (본인) | — | C·R·U·D | — | — |
| E3 매입조건 (전체) | — | — | R | R |
| E4 NDA | R(내 매물에 온 요청) | C(제출)·R(내 요청) | R·U(승인/거절) | R |
| E5 알림 (본인) | R·U(읽음)·수신설정 U | R·U·수신설정 U | R·U | R·U |
| E6 운영 콘텐츠 | — | — | C·R·U·D | R |
| 관심 (본인) | — | C·R·D | R(집계만) | R |
| 문의 티켓 | C·R(본인) | C·R(본인) | R·U(답변·상태) | R |

**항상 제외 4필드** (매입 회원에게 어떤 단계에서도 비공개): 채권기관 · 담당자명 · 직책 · 연락처.

## 4. 이 매트릭스가 만들어내는 화면 — 이것이 전부

### 4-1. 서비스 (공개 영역)

| 화면 | = 데이터 × CRUD |
|---|---|
| 회원가입 | E1.C (역할 선택 매각/매입 → 매입은 법인/개인 분기, 완료 시 매입조건 폼으로 이동) |
| 로그인 | 세션 (비밀번호 재설정 포함) |
| NPL 자동매칭 | E2.R(공개 9필드, 매칭 선별) + 관심.C/D + E4.C(NDA 제출) + E2.R(승인 시 상세 패널) |
| NPL 매각의뢰 | E2.C (컨시어지 접수) |
| 매입조건 등록 | E3.C — **서비스 유일 폼. 가입·마이페이지 모두 여기로** |
| 메인 / 소개 | E6.R |

### 4-2. 마이페이지 — 역할당 4~6개 화면, 그 이상 만들지 않는다

| 화면 | 누구 | = 데이터 × CRUD |
|---|---|---|
| 대시보드 `/my` | 전 회원 | 역할별 요약 R: 매입=이번 주 브리핑·조건/관심/NDA 카드, 매각=내 매물 카드, 겸용=합집합 |
| 내 매물 `/my/seller` | 매각 | E2(본인).R + U(상태 3종) + D요청 + 파생(매칭·마케팅·NDA 현황).R + 주간 활동 요약.R |
| 매입 조건 `/my/demands` | 매입 | E3(본인).R·U·D (+C는 서비스 폼 링크) |
| 관심매물 `/my/portfolio` | 매입 | 관심.R·D |
| NDA 진행 `/my/agreements` | 매입 | E4(본인).R (2단계 상태) |
| 알림센터 `/my/inbox` | 전 회원 | E5.R·U + 문의.C·R |
| 설정 `/my/settings` | 전 회원 | E1(본인).U — 회원정보·비밀번호·알림 수신 **이 3개뿐** |

### 4-3. 관리자 — 데이터당 화면 1개 + 콘텐츠 + 접수함

| 화면 | = 데이터 × CRUD |
|---|---|
| 대시보드 `/admin` | 전 데이터 카운트 R (승인대기 N·검토대기 N·NDA 검토 N·오늘 접수 N) — 각 숫자는 해당 화면으로 클릭 이동 |
| 회원 승인 `/admin/users` | E1.R·U — 목록(검색·필터·페이징) + 상세 모달(첨부 뷰어·NDA/매입조건 이력·역할 관리·보류·비번초기화·탈퇴) |
| 매각의뢰 현황 `/admin/listings` | E2.R·U·D — 검토승인/거절 + 세부내역(40필드) 패널 + 마케팅 패널(8채널·상담·딜단계·매칭일) |
| 매입조건 현황 `/admin/demands` | E3.R |
| NDA · 계약 `/admin/agreements` | E4.R·U (승인/거절 → 즉시 매입회원 열람 해제 + 알림) |
| 접수함 `/admin/inbox` | 문의.R·U (매각의뢰 문의·진행종료 요청·일반 문의) |
| 콘텐츠 4종 `/admin/highlights·press·main-stats(+히어로)` | E6.C·R·U·D ↔ 메인 즉시 반영 |

파트너: 위 관리자 화면 전부 R 전용 (입력 비활성 + 배너).

## 5. 상태 기계 — 전이는 정해진 주체만

```
E1 회원   승인대기 ─관리자─> 활성 | 보류(사유) | 거절        활성 ─관리자─> 차단 | 탈퇴
E2 매물   검토대기 ─관리자─> 공개 | 거절
          공개: 진행중 ─매각회원/관리자─> 협의중 ─> 매각완료
          공개 ─매각회원 요청 + 관리자 승인─> 종료
E4 NDA    제출 완료(매입회원) ─관리자─> 승인 | 거절
```

상태를 바꾸는 순간 = 알림 발생 지점 (아래 6).

## 6. 알림 = 상태 전이의 기록 + 요약 발송

| 트리거 | 수신자 | 채널 |
|---|---|---|
| E1 승인/거절/보류 | 해당 회원 | 인앱+메일 |
| E4 제출 | 매물 소유 매각 회원 + 관리자 | 인앱 |
| E4 승인/거절 | 요청 매입 회원 | 인앱+메일 |
| 일일 다이제스트 (신규 매칭 N + 하이라이트 ≤2 + `?alert=` 링크) | 활성 매입 회원 | 인앱+메일 (매일 08시) |
| 주간 리포트 (NDA +7일·관심·상담) | 활성 매각 회원 | 인앱+메일 (월 08시) |

수신 설정(설정 화면)이 발송을 필터한다. 그 외 알림은 만들지 않는다.

## 7. 삭제 대상 (레거시 — 발견 즉시 제거)

마이페이지·관리자 어디서든 다음이 보이면 이 문서 위반: 정산/계좌/수수료, 투자자 등급(L1~), 구독/티어/크레딧, 조회수 분석 차트, KYC 등급 심사, 커뮤니티/전문가/딜룸, 온보딩 투어, 별도 상세 "화면"(패널·모달이 아닌 페이지 이동).
