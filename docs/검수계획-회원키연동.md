# 회원 Key(user_id) 연동 전면 검수 계획서

> 2026-08-19 · 목표: **모든 업무 데이터가 회원 아이디(user_id)로 유기적으로 연결**되고,
> 리스트→상세 어디서든 "누구의 것인지"가 키로 추적된다. 이메일·이름 문자열 매칭 금지.

## 0. 현재 진단 (연동 구멍)

| 데이터 | 현재 키 | 문제 |
|---|---|---|
| 매입조건 demands | user_id ✅ (신규만) | 기존 시드 3건은 가짜 uuid — 백필 필요 |
| NDA (listing_marketing.nda_requests) | **email 문자열** ❌ | 회원 상세 이력·열람 게이트가 이메일 조인 — user_id 없음 |
| 관심 | **localStorage** ❌ | 서버에 회원별 저장 없음 (기기 바뀌면 소실, 운영자는 합계만) |
| 매각의뢰 접수 | 티켓 user_id ✅ / **매물 미생성** ❌ | 승인해도 npl_listings 로 이어지는 seller_id 연결 경로 없음 |
| 매물 npl_listings | seller_id ✅ (컬럼) | 관리자 검토 화면에 매각 회원 표시·연결 UI 없음 |
| 문의·알림·수신설정 | user_id ✅ | 정상 |

## 1. 10라운드 실행 계획

| R | 작업 | 완료 기준 |
|---|---|---|
| R1 | **키 감사 SQL** — 전 테이블 user 키 무결성 조회(고아 레코드·이메일-only 레코드 수) | 감사 결과표 |
| R2 | **NDA user_id화** — 제출 시 user_id 저장, 열람 게이트·회원 이력·매각 표시를 user_id 우선(이메일 폴백), 기존 데이터 백필 | 게이트가 user_id 로 통과 |
| R3 | **관심 서버화** — favorites 테이블(user_id×listing_id, RLS own) + API + exchange♥/portfolio 연동(localStorage → 서버 마이그레이션) | 다른 기기에서도 관심 유지 |
| R4 | **매각의뢰→매물 연결** — 접수 티켓에 user_id(이미 됨) + 관리자 접수함에서 "매물로 전환" 액션: npl_listings 생성 + seller_id=접수자 | 전환 후 매각 회원 내 매물에 표시 |
| R5 | **demands 백필** — 시드 조건의 user_id 를 시드 회원과 정합화, mine 필터 재검증 | 회원 상세 매입조건 이력 = 본인 것 |
| R6 | **회원 상세 이력 키 전환** — NDA·매입조건 이력을 user_id 조인으로 | 이메일 변경해도 이력 유지 |
| R7 | **리스트 소유자 표시** — 매각의뢰 현황에 매각 회원(이름·회사), 매입조건 현황에 회원명, NDA에 요청 회원 — 전부 users 조인 | 운영자가 키로 추적 가능 |
| R8 | **상세 게이트 전환** — /listing-detail?mode=view 승인 판정 user_id | ✅ |
| R9 | **E2E** — 매입 로그인→관심→NDA 제출(user_id)→승인→열람 / 매각 로그인→내 매물(seller_id) / 관리자 이력 확인 | 전 구간 키 추적 |
| R10 | **회귀 스윕 + 배포** — 기존 기능(다이제스트·주간요약·카운터) user_id 기반 재검증 | 프로덕션 검증 |

## 2. 스키마 변경

```sql
-- R2: nda_requests 배열 요소에 user_id 추가 (jsonb 라 무마이그레이션, 코드 계약만)
-- R3: 관심
create table favorites (
  user_id uuid not null,
  listing_id text not null,
  created_at timestamptz default now(),
  primary key (user_id, listing_id)
);  -- RLS: own select/insert/delete + admin all
```

## 3. 원칙

- 판정·조인은 **user_id 우선, email 은 레거시 폴백**으로만 (한시적).
- 리스트·상세·집계 어디서든 소유자는 users 조인으로 표시 (문자열 복제 금지).
- 각 라운드 완료 시 커밋, R10에서 일괄 배포.
